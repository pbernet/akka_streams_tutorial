# Scala 3 Migration Report

## Outcome

The project has been migrated from Scala 2.13.18 to Scala 3.9.0 and compiles with the Scala 3 artifacts of Pekko, Pekko
HTTP, Pekko Connectors, and Pekko Connectors Kafka.

The migration also addressed the source and runtime issues identified in the original four-part plan. In particular,
application entry points no longer depend on `App` initialization semantics, and the WebSocket and reverse-proxy
examples start correctly.

## 1. Build and dependency migration

The build now uses:

| Component               | Previous version | Migrated version |
|-------------------------|------------------|------------------|
| Scala                   | 2.13.18          | 3.9.0            |
| Pekko actor/stream      | 1.7.0            | 2.0.0-M4         |
| Pekko HTTP              | 1.4.0            | 2.0.0-M1         |
| Pekko Connectors        | 1.3.0            | 2.0.0-M1         |
| Pekko Connectors Kafka  | 1.2.0            | 2.0.0-M1         |
| sbt                     | 1.12.8           | 1.12.15          |
| avro4s                  | 4.1.2            | 5.0.15           |
| ClickHouse Scala client | 1.2.17           | 2.0.0            |

Kafka and the InfluxDB Scala client do not currently publish Scala 3 artifacts, so their Scala 2.13 artifacts are
consumed with `CrossVersion.for3Use2_13`. Pekko transitive dependencies are excluded from the InfluxDB client to prevent
it from reintroducing incompatible Pekko versions.

Pekko HTTP and Connectors 2.0.0-M1 depend on Pekko Core milestone M1, while this project intentionally selects Pekko
Core/Stream 2.0.0-M4. Explicit Pekko dependency-scheme rules document and permit that milestone combination. These rules
should be reviewed when final Pekko 2.0 releases become available.

The Scala 2 migration option `-Xsource:3` was removed because the build now compiles directly with Scala 3.

## 2. Scala 3 source compatibility

The source changes required for Scala 3 include:

- replacing `extends App` with explicit `main(args: Array[String]): Unit` entry points;
- replacing `_` field initialization with `scala.compiletime.uninitialized` where mutable, deferred initialization
  remains necessary;
- updating explicit contextual argument calls to Scala 3 `using` syntax;
- adapting changed overload resolution and type inference with explicit types where needed;
- updating APIs whose signatures changed, including HTTP request attributes, ClickHouse version lookup, S3 results,
  Docling request builders, and selected stream materialized values;
- updating avro4s code to the Scala 3-compatible 5.x API;
- removing obsolete `private[this]` qualifiers.

Companion-object APIs used by other code were retained while executable application state was moved into `main`-owned
scopes or private application instances.

## 3. Pekko Stream queue migration

Pekko Stream 2.0 deprecates the `Source.queue` overloads that accept an `OverflowStrategy`, including the three-argument
overload with `maxConcurrentOffers`; it does not remove them. Pekko 2.0.0-M4 retains these methods with
`@deprecated(since = "2.0.0")`. The affected examples were migrated proactively according to their behavior:

- concurrent producers now feed a `MergeHub` sink;
- one-shot HTTP pool requests use `Source.single`;
- WebSocket and MQTT producers that require acknowledgement use `Source.actorRefWithBackpressure` and actor messaging;
- the JMS error path uses a one-element source connected directly to its existing sink;
- `SlowConsumerDropsElementsOnFastProducer` intentionally retains the deprecated
  `Source.queue(bufferSize, overflowStrategy)` implementation as an educational comparison, with the deprecation
  documented and locally suppressed.

Tests and documentation were updated to match the new materialized values and completion behavior.

Authoritative references:

- [Pekko
  `Source.queue` migration guide](https://pekko.apache.org/docs/pekko/snapshot/stream/operators/Source/queue.html)
  documents the deprecation and provides replacements for every `OverflowStrategy`.
- [Pekko actors/streams interop documentation](https://pekko.apache.org/docs/pekko/snapshot/stream/actor-interop.html#source-queue)
  recommends `Source.queue(bufferSize)`, `Source.actorRefWithBackpressure`, or `MergeHub.source`.
- [Pekko 2.0.0-M4
  `Source.scala`](https://github.com/apache/pekko/blob/v2.0.0-M4/stream/src/main/scala/org/apache/pekko/stream/scaladsl/Source.scala#L1014-L1066)
  shows that both old overloads remain present and are deprecated since 2.0.0.
- [Apache Pekko PR #3095](https://github.com/apache/pekko/pull/3095) explains the deadlock risk, API decision, and
  migration rationale.

## 4. Compiler and IDE issues

The remaining Scala 3 compiler and IntelliJ findings from the original plan were resolved, including indentation,
inferred-type, initialization, contextual-argument, and deprecated stream API issues. The project now completes an
IntelliJ full rebuild without errors.

The only remaining IDE build warning is an unrelated deprecated AWS Java API usage in
`src/test/java/alpakka/firehose/FirehoseEchoIT.java:80`.

## Runtime entry-point follow-up

An initial mechanical `extends App` conversion left startup effects in singleton bodies and introduced no-op `main`
methods. For applications whose asynchronous callbacks referenced the same singleton, this could deadlock class
initialization before logging or network binding occurred.

All migrated entry points were audited and their launch effects moved into real `main` methods. Shared actor systems and
related runtime values are lazy where they must remain on companion objects.

Runtime checks confirmed:

- `WebsocketEcho` starts, logs activity, and accepts browser connections;
- `WebsocketChatEcho` starts and exchanges messages;
- `ReverseProxy` starts its target servers, proxy, clients, and monitor, and produces sustained request and
  circuit-breaker traffic.

All 89 files below were compile-checked as part of the full build. Files marked **runtime-tested** were also launched
and exercised after the entry-point fix.
